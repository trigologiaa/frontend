# US-23 — Finish the purchase and create an order (Phase 2, anticipated)

> **Status: anticipated.** Not part of the pre-delivery. Refine before starting.

**As a** visitor, **I want** to finish my cart by leaving my contact data and receiving an order
number, **so that** the owner can contact me about the services I chose.

Critical point: the order is a **snapshot** (items, prices and total at the time of purchase) and
the cart is emptied **only after** the order was saved; if saving fails, the cart must survive.

Requirement: course class 9 ("Finalizar compra", conditional rendering) and the final project
checkout.

Depends on: [US-13](us-13-cart-page.md), [US-17](us-17-firestore-catalog.md) and
[US-22](us-22-form-validation.md) (reuses the validation approach).

## Scope

Included:

- A "Checkout" button in the cart page (enabled only with items).
- A checkout form: name, email, phone (validated).
- `createOrder` in an `ordersApi` service (`addDoc` into an `orders` collection): buyer, items,
  total, timestamp.
- A confirmation view with the **order id**; the cart is cleared after success.
- Firestore rules: anyone can create an order, only the owner can read them.

Not included:

- Payments, emails, an order management screen for the owner, order history for visitors.

## Acceptance scenarios

```gherkin
Feature: Checkout and order
  Scenario: Checkout is not offered with an empty cart
    Given the cart is empty
    Then I do not see the checkout button

  Scenario: The visitor fills the buyer data
    Given the cart has services
    When I click "Finalizar compra"
    Then I see a form with name, email and phone

  Scenario: Invalid data is rejected
    When I submit the form with an invalid email
    Then I see an error and no order is created

  Scenario: A valid order is created with a snapshot
    When I submit valid data
    Then "createOrder" receives the buyer, the items with their prices and the total

  Scenario: The visitor receives the order number and the cart is cleared
    Given the order was saved
    Then I see "Tu número de orden es <id>"
    And the cart is empty

  Scenario: A failure keeps the cart
    Given saving the order fails
    When I submit valid data
    Then I see an alert and the cart still has my services
```

## Non-functional requirements

- **Privacy:** buyer data is written once and only readable by the owner (rules); no personal data
  in logs or URLs.
- **Accessibility:** labeled fields, announced errors and confirmation.

## Decisions

- **`ordersApi` is its own service** (separate from `productsApi`): different aggregate, same
  seam idea.
- **Clear the cart after the write succeeds**, never before.
- **The order id shown is the document id** generated by Firestore.
